# PLAT019 — native semantic suspension bridge into Bytecode C-prime continuations

Status: **RATIFIED**

Nature: durable non-normative JVM / Truffle / Bytecode DSL suspension-boundary architecture decision

Approved by project owner: **2026-09-10**

GitHub Issue: **#310**

Primary consumer: `PERF006-B3` under GitHub #276 / PERF006-B under #262

Normative effect: **none**. Existing Protos-visible `Future`, `Task`, Closure, call,
cancellation, Error, `ensure`, non-local-return, Actor and Process semantics remain
authoritative.

## Selected architecture — B-prime

A native implementation may participate in semantic suspension only through an
explicit backend-private suspension capability/provenance. Before its Java activation
is abandoned, sufficient resumable state must exist to complete after resume without
retaining or replaying that Java stack. Actual guest continuation capture belongs to
the Bytecode interpreter / PLAT014 C-prime yield boundary. Task suspension is committed
only after the complete top-level continuation has been atomically published to the Task.

The private transport between the suspension-capable native boundary and the
interpreter-owned capture point is deliberately **unspecified**. A returned request,
private control-transfer/exception, generated Bytecode DSL operation, or equivalent
representation is implementation-local if all durable invariants below remain true.

## Why this decision is needed

PERF006-B2 completed source-backed Closure/call/default/send/spread continuation
composition in the Bytecode backend. B3 must map a real pending `Future.value()` onto
that chain. The legacy replay backend can unwind Java through
`ProtosEvaluatorSuspension`, but an escaping Java exception does not itself execute a
Bytecode DSL yield or preserve an arbitrary Java activation as a resumable guest
continuation. Conversely, making a Task externally runnable before the complete C-prime
continuation reaches Task ownership creates a wake-before-publication race.

## Existing authority

- PLAT014: C-prime is the sole cooperative continuation architecture.
- PLAT010/PLAT011: bounded reusable platform carriers; no carrier per suspended Task.
- PLAT017: implementation specialization may not bypass ordinary lookup/extraction.
- Existing Future/Task semantics: lost-wakeup exclusion, waiter removal, stored Error
  identity and cancellation-first resume behavior.
- Existing Closure semantics: extraction, aliasing and rebinding remain ordinary.
- PERF006 ownership: B3 Future/Task; B4 control/unwind; B5 tooling/source; B6 cutover.

## Strongest precedents

### GraalPy and current Bytecode DSL

Current GraalPy uses Bytecode DSL `@Yield`, `ContinuationRootNode`,
`MaterializedFrame` and `ContinuationResult`. The framework itself supports custom
yield operations that can bind the continuation root and materialized frame. This is
the closest maintained precedent for interpreter-owned C-prime capture.

### Espresso

Espresso reinforces that a suspension signal can travel toward the interpreter, but
recoverable execution state is captured at interpreter-controlled frames.
Native/non-interpreter frames are an explicit continuation boundary concern.

### GraalJS

GraalJS uses private `YieldException` control flow, but resumable nodes save the phase
needed for re-entry before propagating it. This shows that exception-shaped transport
can be correct; what is not correct is treating the escaped Java stack itself as the
continuation. This is the main reason B-prime leaves transport unspecified.

### TruffleSqueak

TruffleSqueak externalizes PC/SP and materializes the active Context before throwing
`ProcessSwitch`. The ordering strongly supports Protos' two-phase rule: materialize
resumable state first; only then make the logical execution externally dispatchable.

### TruffleRuby

TruffleRuby Fiber execution is tied structurally to Truffle/JVM threads and can use
virtual-thread Fibers. This is a real but deliberately rejected family for Protos
because PLAT010/011/014 require suspended Tasks not to consume one carrier each.

### Apple Pkl

Apple Pkl is a real Truffle language. Its external-reader infrastructure uses Java
Future/CompletableFuture and resolves synchronously with `Future.get()` where needed.
That is correct for Pkl's semantics, but not for Protos' transparent Task suspension.
Pkl supplies important negative evidence: do not impose continuation machinery on
ordinary native operations that do not semantically suspend.

### SOMns

SOMns actor/promise handling schedules logical follow-up work rather than retaining a
blocked carrier, reinforcing independent logical ownership.

### Mozart-Graal

Historical Mozart-Graal used the old `com.oracle.truffle.coro.Coroutine` mechanism
with reserved coroutine stacks. It proves host-stack preservation is possible, but
through a historical runtime direction with the wrong physical-resource model for
Protos.

### PorcE

PorcE makes continuations explicit through closures/call targets. It validates
explicit resumability but would be unnecessarily pervasive as Protos' general model.

## Cross-implementation conclusion

The relevant implementations converge on this invariant:

> An arbitrary Java/native activation is not the guest continuation. Resumable state
> must be explicit before that activation is abandoned, and guest continuation capture
> belongs to an interpreter or another explicitly resumable execution substrate.

The transport can differ. PLAT019 selects the invariant, not the transport spelling.

state. The target is O(live suspended logical state), not zero memory.

## Durable constraints

1. No Protos-visible semantic change or public Continuation/`await`.
2. Ordinary non-suspending native Closures keep the current simple fast path.
3. Suspension capability is explicit and backend-private.
4. Capability follows native implementation provenance through ordinary Closure
   extraction, aliasing and rebinding.
5. No selector-specific `Future.value` pet is required for correctness.
6. Before Java/native activation abandonment, sufficient explicit resumable state exists.
7. Java/native stack itself is never the guest continuation.
8. Native-to-interpreter transport representation is deliberately unspecified.
9. Actual C-prime capture belongs to the Bytecode interpreter/yield substrate.
10. Already-terminal `Future.value()` stays synchronous and creates no continuation.
11. Task suspension uses dependency/capture-pending then continuation publication.
12. Ready/cancel during capture cannot enqueue before continuation publication.
13. Publication state is Task-local; no global continuation registry/lock.
14. No ThreadLocal Task identity/authority is introduced.
15. Cancellation-first resume semantics remain exact.
16. Lost-wakeup/waiter-removal semantics remain exact.
17. Stored Future Error identity remains exact.
18. Suspended Tasks release bounded reusable carriers.
19. Memory is O(live suspended C-prime depth + live wait relationship + O(1) Task state).
20. Independent Tasks/Actors/Processes do not acquire unnecessary coordination.
21. Resume does not replay completed guest/native effects.
22. Ordinary native hot paths do not pay a universal Outcome/state-machine tax.
23. B3 does not absorb B4 control/unwind migration.
24. B3 does not absorb B6 normal-source cutover/replay retirement.
25. A future host-backed operation may reuse this mechanism only if approved semantics
    genuinely require logical suspension.
26. Changing only the private transport representation is an implementation refactor,
    not a new PLAT decision, while all constraints remain true.
27. Any newly exposed durable architecture or observable semantic choice stops the slice
    and crosses the normal Dxxx/PLATxxx approval gate.

## Required PERF006-B3 evidence

B3 must prove at least:

- terminal `Future.value()` synchronous fast path;
- direct pending `future.value()` suspend/resume;
- extracted `f: future.value; f()` suspend/resume;
- alias/rebinding preservation;
- Future resolve/fail/cancel outcomes;
- exact stored Error identity;
- cancellation-before-wait and cancellation-while-pending;
- cancellation versus ready precedence at resume;
- waiter detachment and lost-wakeup exclusion;
- wake during capture-pending;
- cancellation during capture-pending;
- neither race can enqueue before top-level continuation publication;
- deep B2 caller composition without replay;
- completed targets/arguments/defaults/sends/spreads are not repeated;
- Task-local continuation ownership;
- carrier reuse while the logical Task is suspended;
- many independently suspended Tasks without O(Task) carrier growth;
- no global continuation table/lock/thread identity;
- ordinary non-suspending native calls retain their direct fast path.

## B3 release and preferred first slice

Publication of this ratification releases PERF006-B3 for bounded implementation.

Preferred first mechanical slice:

**PERF006-B3A — Task capture-pending and atomic continuation publication**

B3A should establish and test the two-phase Task ownership/publication protocol without
yet making standard `Future.value()` the production suspension-capable native. This
isolates wake/cancel-during-capture races before the native bridge is connected.

## Deliberately deferred

PLAT019 does not select:

- Java class/interface names for the private capability/descriptor;
- return versus private exception/control-transfer versus generated-operation transport;
- exact capture-pending field packing;
- lock-free versus small-lock Task publication internals;
- public async/await/Continuation constructs;
- new network/filesystem async semantics;
- distributed serialization/migration of live continuations;
- B4 control/unwind representation;
- B5 debugger/source projection details beyond existing authority;
- B6 cutover mechanics.

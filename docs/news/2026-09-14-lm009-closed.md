# LM009 closed: Protos reaches a reproducible VS Code IDE baseline

Today, September 14, 2026, Protos closes **LM009 — Editor & IDE Language
Maturity**, completing the first end-to-end reference integration for developing
Protos from a modern IDE.

LM009 was deliberately built around one principle: **the editor must remain
subordinate to the real Protos language, runtime, parser, resolver and tooling
authorities**. The VS Code extension is an integration layer, not a second
implementation of the language.

## From development tree to product artifact

The final LM009 tranche focused on a deceptively important boundary: proving
that the thing that works in the development tree is also the thing a user can
actually install, run and debug.

The resulting product path is:

```text
Protos source
    ↓
VS Code extension build
    ↓
canonical VSIX
    ↓
CI artifact
    ↓
clean installation
    ↓
real Run
    ↓
real Debug
```

D127 ratified the thin-client dependency/runtime boundary, while D128 ratified
the deterministic canonical VSIX identity.

The canonical VSIX is reproducible from clean worktrees. Independent builds of
the same source revision produce the same canonical SHA-256 artifact, while
VSCE remains the authority for extension/package semantics.

## The packaged artifact is the product

LM009-I proved that the canonical VSIX produced by CI is more than a packaging
exercise.

The exact CI artifact was installed into a clean VS Code environment without
using `extensionDevelopmentPath`.

From that installed artifact, Protos was successfully exercised through:

- `.protos` language association and extension activation;
- **Run Current File** using the real Protos runtime;
- real debugger startup;
- source breakpoints and verified stop locations;
- stack frames;
- activation-local scopes and representative values;
- stepping;
- continue;
- clean debugger termination.

This closes the loop between editor development and actual product consumption.

## A thin editor by design

The extension does not become a second Protos runtime.

The Protos runtime and language-server authority remain external and continue to
be selected through the existing `protos.runtime.executable` boundary.

That keeps the editor compatible with the same runtime/tooling architecture
used outside VS Code and avoids coupling the extension artifact to Java,
JAR/classpath or runtime implementation details.

## Release boundary

LM009-I4 establishes **GitHub Release** as the canonical public distribution
record for the extension.

The extension has its own independent SemVer sequence, separate from Protos
runtime versioning. The canonical VSIX is attached to the GitHub Release rather
than committed to the repository.

Marketplace and Open VSX remain optional future distribution mirrors. They are
not prerequisites for LM009 closure and are not automatically published from
ordinary `main` activity.

## What remains for LM010

Closing LM009 does not mean every possible IDE feature is complete.

**Hover, completion and signature help are explicitly deferred to LM010.**
They will be built from Protos' real static language authorities rather than
from a parallel editor-side semantic model.

Formatter work, rename/refactoring, debugger mutation/evaluation and other
advanced capabilities likewise remain later work.

## The result

LM009 now provides a reproducible reference baseline:

```text
Development integration  ✅
Production VSIX          ✅
Reproducible packaging   ✅
CI artifact              ✅
Clean installation       ✅
Real execution           ✅
Real debugging           ✅
Release policy           ✅
```

The important result is not simply that Protos has a VS Code extension.

The important result is that the extension has crossed the boundary from
**development integration** to a **reproducible, installable, executable and
debuggable product artifact**, while keeping the language and runtime
authorities where they belong.

**LM009 is now CLOSED.**

The next editor chapter begins with **LM010**.

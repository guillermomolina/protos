# Protos 0.3.0: the optimizing runtime era begins

**September 14, 2026**

Today Protos **0.3.0** is available as a public prerelease.

This milestone follows the completion of PERF006 and marks an important transition in the runtime: C′ is now the production execution generation, and ordinary intended JVM execution uses the selected optimizing Graal/Truffle runtime.

## What this milestone means

PERF006 was not simply a runtime dependency update. It completed the production cutover to the C′ continuation architecture and retired the replay-heavy execution path from normal production execution.

The resulting runtime preserves the existing semantic contracts around calls, suspension and resumption, cancellation, structured cleanup, errors, non-local returns, source identity and tooling while allowing Truffle compilation to operate on the current execution architecture.

## What shipped in 0.3.0

The published 0.3.0 distribution includes:

- the selected optimizing `HotSpotTruffleRuntime` execution plane;
- the C′ production execution generation;
- the validated portable JVM distribution;
- the Test Tool stdout-completion correction from DIST003-D1, ensuring the bootstrap markers are completed before normal tool termination.

## What the performance evidence shows

The PERF006 controlled optimizer-vs-fallback measurements used the same Protos sources, host JDK, workload sources, container topology and measurement policy while changing only the Truffle optimizer runtime/compiler closure.

All five retained workloads are faster in steady state with the optimizer. The retained steady-state median benefit ranges from approximately **1.06x to 1.73x**.

The historical replay bottleneck is also gone: the production profile no longer shows the old replay cleanup pathology, and the historical `HashMap$KeyIterator.next` signal is absent from the current D3 profile.

These results should not be confused with the larger historical end-to-end timing changes observed during the PERF006 architecture transition. Those changes combined the C′ execution cutover, replay retirement, runtime composition and harness evolution; they are not optimizer-only measurements.

## Prerelease status

This is a **public prerelease**, not a claim of complete CI coverage.

Repository-wide automatic CI execution remains intentionally suspended for the affected paths under GITHUB017 / #492 after TOOL005 / #468. Those limitations are disclosed in the release evidence and do not change the published artifact identity.

## What comes next

The optimizing runtime is now the foundation for the next generation of performance work. In particular, PERF008 separately investigates the current `continueAt` hotspot without assuming in advance that the generated frame represents a defect or that a particular optimization is required.

At the same time, Protos continues its language, standard-library, tooling and developer-experience tracks independently of the 0.3.0 publication.
